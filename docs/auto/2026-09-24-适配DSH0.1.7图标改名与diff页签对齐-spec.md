# dsh-better-sidebar-svn 修改计划 · Spec

- **日期**: 2026-09-24
- **模块**: dsh-better-sidebar-svn（SVN 源代码管理侧边栏面板插件）
- **当前版本**: v0.2.0
- **范围**: 仅本插件（host 半不动，只改 client 半 + 依赖声明 + 文档）

---

## 1. 目标

让插件回到 DSH `0.1.7-rc.1` / dsh-better-sidebar `0.21.1` 这条支持线上，并让 SVN 的 diff 页签与内置同名页签表现一致：

1. **图标导出改名迁移**（必须）：修掉 client 半引用的 9 个已消失的图标名。
2. **diff 页签对齐内置**（本次诉求）：`dsh-better-sidebar-svn:diff` 的标题与图标对齐内置 `diff` 页签。
3. **依赖声明收敛**：`peerDependencies` / `dsh.client.inject` 里已不存在的包清掉，版本线抬到 `0.1.7-rc.1`。

非目标：不改 host 半任何路由与 svn CLI 调用；不改面板交互；不改版本号与 tag（发布由人工决定）。

## 2. 现状事实（据源码与实测）

### 2.1 图标导出改名（已实锤）

- DSH `0.1.7-rc.1` 的 `@deepseek-ai/dsh-client-ui-primitives`（共导出 268 个成员）已把图标具名导出**整族改名**：`...16` → `...OutlineRegular` / `...OutlineMedium`。
- 实测：该模块 268 个导出中，`IconBranchOutline16` 等 9 个旧名**命中数为 0**。
- 插件 client 半仍在用旧名，共 9 个名字 / 20 处：
  - `src/client/index.tsx:17` `IconBranchOutline16`（1 处使用）
  - `src/client/SvnDiffTab.tsx:13` `IconRefreshOutline16`（1 处使用）
  - `src/client/SvnView.tsx:12-15` `IconBranchOutline16`、`IconCheckOutline16`、`IconCodeOutline16`、`IconCopyOutline16`、`IconDownloadOutline16`、`IconListPenOutline16`、`IconPlusOutline16`、`IconRefreshOutline16`、`IconTrashOutline16`
- 运行时后果：`require()` 拿到 `undefined`，React 渲染抛 `Element type is invalid`，SVN 面板与「+」菜单崩。
- 旁证：插件管理器日志 `.dsh-market/log.ndjson` 记录 2026-09-24T09:02:38Z `dsh-better-sidebar-svn -> on: on ok=true`，20 秒后（09:02:58Z）被关掉 —— 就是撞上该崩溃的时刻。
- 构建侧现状：本地 `node_modules` 锁在旧线（`dsh-better-sidebar@0.13.0`、`@deepseek-ai/dsh-client-ui-primitives@0.1.0-rc.7`），因此直接 `pnpm build` 只会重建出同样的旧名字。

### 2.2 diff 页签不一致（本次诉求）

- 内置 `dsh-better-sidebar@0.21.1` 的两个 descriptor（`lib/client.js`）：
  - `{ id: "git", title: () => t("changes"), icon: changesTabIcon, order: 20 }`
  - `{ id: "diff", title: () => t("changes"), icon: changesTabIcon, order: -1, hidden: true, dedupeKey: tab => tab.id }`
  - 其中 `t("changes")` = 「文件变动」，`changesTabIcon = (size) => themed(css.changes, <VscGitCommit size={size} />)`。
- 即：内置的「git 主面板」与其「diff 页签」**同标题、同图标**（VS Code 的 git-commit 字形）。
- 本插件现状（`src/client/index.tsx`）：
  - 主面板 `{ id: 'svn', title: '源代码管理SVN', icon: IconBranchOutline16, order: 25, single: true }`
  - diff 页签 `{ id: 'dsh-better-sidebar-svn:diff', title: '源代码管理SVN', icon: 自定义 IconDiffOutline16, hidden: true }`
  - 源码注释声称「与内置 Git 的 diff 标签页同一惯例：标题沿用主面板名，图标用 diff 图形」—— 该描述与 0.21.1 实际行为不符。
- 侧边栏设置页实测（用户截图）：7 个条目标题分别为 `文件变动(git)` / `源代码管理SVN(svn)` / `任务管理(subagent)` / `侧边对话(sidechat)` / `文件(editor)` / `文件变动(diff)` / `源代码管理SVN(dsh-better-sidebar-svn:diff)` —— 最后一条是唯一既不叫「文件变动」、也不带 changes 字形的一条。

### 2.3 依赖声明现状

- `peerDependencies` 中 `@deepseek-ai/dsh-client-runtime`、`@deepseek-ai/dsh-client-web-react` 在 npm 上**不存在 `0.1.7-rc.1`**（已从 0.1.7 线移除）；其余（`dsh-host-webserver` / `dsh-session` / `dsh-settings` / `dsh-client-ui-primitives`）存在。
- `dsh.client.inject` 里的 `@deepseek-ai/dsh-client-runtime` 同样指向已消失的包。0.1.7 的清单类型中该字段注释为「Informational package-name dependencies, not Cordis service injection」，因此不影响加载，属可清理项。
- host 半依赖的服务在 0.1.7-rc.1 中均存在：`webServer.register({ kind: 'exact' })`、`sessions.get().header.cwd`（`SessionHeader.cwd` 仍在）、`webRuntime.trustedHosts`（`dsh-web-app` 仍 `provide('webRuntime', …)`）。路由语义与 svn CLI 调用**无需改动**。

### 2.4 host 半 handler 的类型面变了（抬依赖后 `tsc` 才暴露）

- `dsh-better-sidebar@0.13.0` 的 `Context.webServer.register` 接受 node 类型；`0.21.1` 改成了它自己的结构性类型：

  ```ts
  interface SidebarHttpRequest { url?: string; method?: string; headers: Record<string, string | string[] | undefined>; [Symbol.asyncIterator](): AsyncIterator<string | Uint8Array> }
  interface SidebarHttpResponse { statusCode: number; writeHead(status: number, headers?: Record<string, string>): void; end(body?: string | Uint8Array): void }
  ```

  设计意图是「不让 Node 全局类型漏进声明图」，运行时传入的仍是真正的 node `IncomingMessage` / `ServerResponse`。
- 实测报错：`src/index.ts(197,7): error TS2322` —— 插件把 handler 参数标成 `IncomingMessage` / `ServerResponse`（更窄），与声明不符。
- 该类型只在 `./src/*` 子路径可见，包根 `export type { Context }` **不导出** `SidebarHttpRequest` / `SidebarHttpResponse`；本插件又明确避免对 `./src/*` 做解析。
- 连带影响：`src/wire.ts` 的 `readJsonBody` 走 `req.on('data'|'end'|'error')`（node 专有），无法接受结构性请求面；`writeOk/writeError/writeJson`、`createTrustFence`、`header` 只用到 `writeHead`/`end`/`headers`，本来就兼容。

## 3. 需求细节

### 3.1 图标改名迁移（必须）

把上述 9 个名字按 `...16` → `...OutlineRegular` 一对一替换：

| 旧名 | 新名 |
|---|---|
| `IconBranchOutline16` | `IconBranchOutlineRegular` |
| `IconCheckOutline16` | `IconCheckOutlineRegular` |
| `IconCodeOutline16` | `IconCodeOutlineRegular` |
| `IconCopyOutline16` | `IconCopyOutlineRegular` |
| `IconDownloadOutline16` | `IconDownloadOutlineRegular` |
| `IconListPenOutline16` | `IconListPenOutlineRegular` |
| `IconPlusOutline16` | `IconPlusOutlineRegular` |
| `IconRefreshOutline16` | `IconRefreshOutlineRegular` |
| `IconTrashOutline16` | `IconTrashOutlineRegular` |

选择 `...Regular` 而非 `...Medium` 的理由：原本 `...16` 是「16px 常规描边」语义；`Regular` / `Medium` 两族在 0.1.7 中同时存在且都接受 `size?: number`，插件各处按 `size={14}` / `size={16}` 传参，取 Regular 与内置面板的字重观感一致。

### 3.2 diff 页签对齐内置

- `id: 'dsh-better-sidebar-svn:diff'` 的 descriptor 调整为：
  - `title`: `'源代码管理SVN'` → `'文件变动'`
  - `icon`: 自定义 `IconDiffOutline16` → 与内置 `changesTabIcon` 同款字形（VS Code git-commit 图形）
  - 其余字段（`hidden: true`、`dedupeKey: tab => tab.id`、`component`）保持不变。
- 主面板 `{ id: 'svn' }` **不动**：标题保持「源代码管理SVN」，图标保持 `IconBranchOutlineRegular`。
- 实现方式：内置 `changesTabIcon` 是 better-sidebar 内部模块的私有值，且本插件已明确避免对子路径（`dsh-better-sidebar/src/*`）做运行时解析；因此按既有做法把该字形 SVG **内联**到 `src/client/index.tsx`，并注明来源与 MIT 许可（与现有 `IconDiffOutline16` 的处理方式一致）。原 `IconDiffOutline16` 内联定义随之删除（变为死代码）。

### 3.3 依赖声明收敛

- `peerDependencies`：
  - 删除 `@deepseek-ai/dsh-client-runtime`、`@deepseek-ai/dsh-client-web-react`（0.1.7 线已无此包）。
  - `@deepseek-ai/dsh-client-ui-primitives`、`@deepseek-ai/dsh-host-webserver`、`@deepseek-ai/dsh-session`、`@deepseek-ai/dsh-settings` 抬到 `^0.1.7-rc.1`。
  - `dsh-better-sidebar`: `>=0.12.0` → `^0.21.1`。
- `dsh.client.inject`：移除已消失的 `@deepseek-ai/dsh-client-runtime`，其余保留。
- 开发依赖：本地 `node_modules` 必须解析到 `dsh-better-sidebar@0.21.1` 与 `@deepseek-ai/dsh-client-ui-primitives@0.1.7-rc.1`，否则 `tsc` 仍按旧类型校验、改名会被判错。

### 3.4 host 半类型适配（行为不变）

- `src/wire.ts`：不再 `import type { IncomingMessage, ServerResponse } from 'node:http'`，改为在本文件声明两个**结构性最小面** `SidebarRequestLike` / `SidebarResponseLike`（与上游 `SidebarHttpRequest` / `SidebarHttpResponse` 结构一致，宽进：响应面只声明路由真正用到的成员）。据此收窄全部辅助函数的签名。
- `readJsonBody`：由 `req.on('data'|'end'|'error')` 改为 `for await (const chunk of req)`，并保留原有的错误契约（流错误 → `bad-request`，空体 → `{}`，非法 JSON → `bad-request`）。
- `src/index.ts`：删掉 `node:http` 类型 import；handler 参数**不加标注**，交给 `register` 的上下文推断。
- 取舍：不引入类型断言（`as unknown as`），也不从 `dsh-better-sidebar/src/*` 取私有类型 —— 结构性类型天然双向兼容，且不增加对上游内部路径的耦合。
- 非目标重申：**不改**任何路由路径、`kind`、请求/响应语义与 svn CLI 调用；这次只动类型面与读体实现方式。
