## 1. 背景与问题

用户安装的 DSH 运行时为 **0.2.0-rc.2**，profile 以 `github:ztyhehe/dsh-better-sidebar-svn#v0.3.0` 直装本插件，启动时被 profile 兼容性闸门拦下：

```
dsh: skipping profile bundle "dsh-better-sidebar-svn": Error: Plugin
dsh-better-sidebar-svn@0.3.0 is incompatible with dsh 0.2.0-rc.2:
peerDependencies {"@deepseek-ai/dsh-client-ui-primitives":"^0.1.7-rc.1",
"@deepseek-ai/dsh-host-webserver":"^0.1.7-rc.1","@deepseek-ai/dsh-session":"^0.1.7-rc.1",
"@deepseek-ai/dsh-settings":"^0.1.7-rc.1"}
```

即**「文档/元数据声称的支持线」与「实际运行时版本」冲突**：

- `CHANGELOG.md` 的 `[0.3.0]` 与 `README.md` 写「要求 DSH ≥ `0.1.7-rc.1`」；
- 但 `package.json` 的四个 `@deepseek-ai/dsh-*` peer 写成 `^0.1.7-rc.1`，按 caret 语义**上界是 `0.2.0`（不含）**，`0.2.0-rc.2` 落在区间外；
- 于是同一份元数据里「声称的支持线」与「声明的版本区间」自相矛盾，插件在 0.2.x 运行时不加载。

## 2. 现状事实（据源码/实测）

### 2.1 闸门规则（来自运行时实现，非推测）

DSH 的 profile 兼容性检查 `evaluatePluginCompatibility()`（`@deepseek-ai/dsh-app-boot`）逻辑：

- 只检查 `peerDependencies` 中名字为 `@deepseek-ai/dsh` 或以 `@deepseek-ai/dsh-` 开头的项；
- 判定条件为 `semver.satisfies(runtimeVersion, range, { includePrerelease: true })`；
- 不匹配即拒绝加载（除非为该 `name@version` + 该精确运行时版本授予 exemption）。

因此 `dsh-better-sidebar` 自身的 peer 不参与该判定，**冲突面就是那四个 `@deepseek-ai/dsh-*` peer 区间**。

### 2.2 插件实际依赖的运行时能力（据 src/）

| 位置 | 用到的东西 |
|---|---|
| `src/index.ts` | `dsh-better-sidebar` 的 `Context`：`ctx.webServer.register`、`ctx.sessions.get(id).header.cwd`、`ctx.webRuntime.trustedHosts` |
| `src/client/index.tsx` | `dsh-better-sidebar` 的 `Context` / `TabComponentProps` / `SidebarTab`（`./client/service`）、`IconBranchOutlineRegular` |
| `src/client/SvnView.tsx` | primitives 的 `Button/Input/Menu/Modal/writeClipboard` + 9 个 `...OutlineRegular` 图标 |
| `src/client/SvnDiffTab.tsx` | primitives 的 `IconRefreshOutlineRegular` |

插件源码**不直接** import `@deepseek-ai/dsh-session` / `dsh-settings` / `dsh-host-webserver`；这三项 peer 是「运行时代际声明」——它们随 DSH 一起发版，用来把插件绑定到某条支持线。

### 2.3 实测：0.2.x 运行时下逐项核对（全部通过）

以本机真实 0.2.x 运行时的包为准：DSH `0.2.0-rc.2`，`@deepseek-ai/dsh-client-ui-primitives|dsh-host-webserver|dsh-session|dsh-settings` 均为 `0.2.0-rc.2`，`dsh-better-sidebar` 为 `0.24.1`（其 peer 声明 `@deepseek-ai/dsh-*: ^0.2.0-rc.1`，即该插件本身就是 0.2.x 线）。

| 核对项 | 结论 |
|---|---|
| 9 个图标具名导出（`IconBranchOutlineRegular` 等） | 0.2.0-rc.2 的 `icons/index.d.ts` 全部存在，且 `index.d.ts` 有 `export * from './icons/index.tsx'` |
| `Input` 组件 props | 0.2.0-rc.2 与 0.1.7-rc.1 同为 `{icon?, className?} & InputHTMLAttributes<HTMLInputElement>`，`onChange` / `onKeyDown` 仍按原生事件类型回调 |
| `Button/Menu/Modal/writeClipboard` | 0.2.0-rc.2 `index.d.ts` 仍在导出 |
| better-sidebar 0.24.1 的 `Context` 面 | `webServer.register` / `registerUpgrade`、`sessions.get(id).header.cwd`、`webRuntime.trustedHosts` 均保留；`exports` 仍提供 `.` / `./client` / `./client/service` |
| `tsc --noEmit`（对 0.2.0-rc.2 + better-sidebar 0.24.1 类型） | **0 error** |
| `tsc -p tsconfig.build.json` + `tsconfig.client.json` + `bundle-client.mjs` | 全部 exit 0 |
| 构建产物 `lib/` 与仓库已提交 `lib/` 对比（`diff -rq`） | **完全一致**（无字节差异 ⇒ 无需改源码、无需重建产物） |
| `node --test tests/*.test.ts` | 14/14 通过 |
| 闸门复现与验证 | 现区间 → REJECT（复现用户报错）；改为 `^0.1.7-rc.1 \|\| ^0.2.0-rc.1` → **PASS** |

### 2.4 支持线矩阵（实测 `evaluatePluginCompatibility`，选用区间 `^0.1.7-rc.1 || ^0.2.0-rc.1`）

| 运行时 | 结果 |
|---|---|
| `0.1.6-alpha.2` | REJECT（符合预期：本插件自 0.3.0 起放弃 0.1.6 线） |
| `0.1.7-rc.1` / `0.1.7-rc.2` / `0.1.7` / `0.1.8` | OK |
| `0.2.0-rc.1` / `0.2.0-rc.2` / `0.2.0` / `0.2.3` | OK |
| `0.3.0` | REJECT（未验证的未来大版本，不提前放行） |

## 3. 需求细节

1. 把四个 `@deepseek-ai/dsh-*` peer 区间从 `^0.1.7-rc.1` 改为 **`^0.1.7-rc.1 || ^0.2.0-rc.1`**：既解除 0.2.x 的误拦，也不丢弃已在支持的 0.1.7 线。
2. 版本号 `0.3.0` → `0.3.1`，`CHANGELOG.md` 增 `[0.3.1]` 条目，写明「支持线：DSH `0.1.7-rc.1` ~ `0.2.x`」与本次修复的成因。
3. `README.md` 与 `AGENTS.md` 中「对应 DSH ≥ 0.1.7-rc.1」的表述同步为「`0.1.7-rc.1` ~ `0.2.x`（< 0.3.0）」，消除文档与元数据的二次冲突。
4. 按仓库规范补 `docs/auto/` spec + plan 并在 `AGENTS.md`「本次规划」表登记。

## 4. 非目标

- **不改插件功能与 UI**（`src/` 与 `lib/` 不动；实测 0.2.x 下产物本就一致）。
- **不放行 `0.3.x`**：尚无 0.3 运行时可供验证，不提前声明。
- **不动 `dsh-better-sidebar` peer（`^0.21.1`）**：caret 已覆盖 0.24.1，且该包不参与闸门判定。
- **不动 `devDependencies`（仍 0.1.7-rc.1）**：本机 0.1.7 线工具链可用且构建产物与 0.2.x 下一致；抬 devDep 需联网重装，收益为零。
- **不代替发布**：只做本地提交与本地 tag，推送/改 profile 安装引用由人工决定。
